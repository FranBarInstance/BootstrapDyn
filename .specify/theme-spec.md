# Theme Specification — BootstrapDyn

This document specifies the file naming convention, load order, and creation procedure for BootstrapDyn theme modules. It is referenced by [`.specify/spec.md`](spec.md) Section 10.

## 1. Theme Module Substitute Model

Theme files are **module substitutes**, not additive overrides. A custom theme module must replace the matching `dist/default-*.css` file in the load list. Do not load both files for the same concern.

The standard theme creation procedure is to copy the relevant `dist/default-*.css` file, rename it for the theme module, and edit variable values in the copy. Because theme files replace defaults, each replacement file must provide all variables required for that concern.

`contrast-dyn.css` remains optional and must be loaded after `bootstrap-dyn.css` when used.

`dist/bootstrap-dyn.css` and `dist/contrast-dyn.css` are **never** part of a theme. They are fixed pipeline outputs consumed as-is.

## 2. File Naming Convention

### 2.1 Suffix Convention

Every themeable CSS module file **must** end with one of the canonical suffixes listed below. The prefix before the suffix is the theme name and can vary freely.

### 2.2 Canonical Suffixes and Load Order

The load order is determined by the suffix, not the prefix. Files are concatenated in the following sequence:

| # | Suffix | Concern | Example |
|---|--------|---------|---------|
| 1 | `-color.css` | Color palette, contrasts, derived color vars | `default-color.css`, `dark-color.css` |
| 2 | `-typography.css` | Font families, sizes, weights, line heights | `default-typography.css`, `winter-typography.css` |
| 3 | `-spacing.css` | Spacing scale and derived spacing tokens | `default-spacing.css` |
| 4 | `-corners.css` | Border radius tokens | `default-corners.css` |
| 5 | `-shadows.css` | Box shadow tokens and elevation scale | `default-shadows.css` |
| 6 | `-borders.css` | Border width, style, and color tokens | `default-borders.css` |
| 7 | `-forms.css` | Form control sizing tokens | `default-forms.css` |
| 8 | `-layers.css` | Z-index layer tokens | `default-layers.css` |
| 9 | `-layout.css` | Breakpoint and container max-width tokens | `default-layout.css` |
| 10 | `-motion.css` | Transition and animation tokens | `default-motion.css` |
| 11 | `-sizing.css` | Width, height, and dimension tokens | `default-sizing.css` |
| 12 | `-grid.css` | Grid module (containers, rows, columns) | `default-grid.css` |

### 2.3 Fixed Files (Non-Themeable)

These files are **not theme-specific** and must always use their exact canonical names:

| # | Filename | Purpose |
|---|----------|---------|
| 13 | `bootstrap-dyn.css` | Component CSS with `var(...)` references |
| 14 | `contrast-dyn.css` | Optional contrast behavior rules |

### 2.4 Naming Rules

1. **One file per suffix per directory.** The bundler expects exactly one match per suffix in the input directory. If multiple files share the same suffix, the first match (sorted alphabetically) is used and a warning is emitted.

2. **Prefix is the theme name.** The part before the suffix identifies the theme. Examples:
   - `default` — Bootstrap defaults (generated by the extractor pipeline)
   - `dark` — A dark theme variant
   - `custom` — Any user-defined theme name

3. **Valid examples:**
   ```
   default-color.css
   dark-color.css
   winter-typography.css
   mytheme-spacing.css
   ```

4. **Invalid examples:**
   ```
   colors.css          ← missing hyphen before concern
   theme.color.css     ← dot instead of hyphen as separator
   dark-colors.css     ← concern name doesn't match canonical suffix ("colors" vs "color")
   ```

### 2.5 Suffix Derivation

The canonical suffixes are derived from `extractor/constants.js`. The concern name in each constant maps to the suffix:

| Constant | Suffix |
|----------|--------|
| `DEFAULT_COLOR` → `default-color.css` | `-color.css` |
| `DEFAULT_TYPOGRAPHY` → `default-typography.css` | `-typography.css` |
| `DEFAULT_SPACING` → `default-spacing.css` | `-spacing.css` |
| `DEFAULT_CORNERS` → `default-corners.css` | `-corners.css` |
| `DEFAULT_SHADOWS` → `default-shadows.css` | `-shadows.css` |
| `DEFAULT_BORDERS` → `default-borders.css` | `-borders.css` |
| `DEFAULT_FORMS` → `default-forms.css` | `-forms.css` |
| `DEFAULT_LAYERS` → `default-layers.css` | `-layers.css` |
| `DEFAULT_LAYOUT` → `default-layout.css` | `-layout.css` |
| `DEFAULT_MOTION` → `default-motion.css` | `-motion.css` |
| `DEFAULT_SIZING` → `default-sizing.css` | `-sizing.css` |
| `DEFAULT_GRID` → `default-grid.css` | `-grid.css` |

## 3. Recommended CSS Load Order

### 3.1 Default Modules

```html
<link rel="stylesheet" href="dist/default-color.css">
<link rel="stylesheet" href="dist/default-typography.css">
<link rel="stylesheet" href="dist/default-spacing.css">
<link rel="stylesheet" href="dist/default-corners.css">
<link rel="stylesheet" href="dist/default-shadows.css">
<link rel="stylesheet" href="dist/default-borders.css">
<link rel="stylesheet" href="dist/default-forms.css">
<link rel="stylesheet" href="dist/default-layers.css">
<link rel="stylesheet" href="dist/default-layout.css">
<link rel="stylesheet" href="dist/default-motion.css">
<link rel="stylesheet" href="dist/default-sizing.css">
<link rel="stylesheet" href="dist/default-grid.css">
<link rel="stylesheet" href="dist/bootstrap-dyn.css">
<link rel="stylesheet" href="dist/contrast-dyn.css"> <!-- optional -->
```

### 3.2 Custom Theme Modules

Load either `dist/default-color.css` or `theme/color.css`, never both:

```html
<link rel="stylesheet" href="theme/color.css">
<link rel="stylesheet" href="theme/typography.css">
<link rel="stylesheet" href="theme/spacing.css">
<link rel="stylesheet" href="theme/corners.css">
<link rel="stylesheet" href="theme/shadows.css">
<link rel="stylesheet" href="theme/borders.css">
<link rel="stylesheet" href="theme/forms.css">
<link rel="stylesheet" href="theme/layers.css">
<link rel="stylesheet" href="theme/layout.css">
<link rel="stylesheet" href="theme/motion.css">
<link rel="stylesheet" href="theme/sizing.css">
<link rel="stylesheet" href="theme/grid.css">
<link rel="stylesheet" href="dist/bootstrap-dyn.css">
<link rel="stylesheet" href="dist/contrast-dyn.css"> <!-- optional -->
```

### 3.3 Single-File Bundle

For production deployments, use the bundler to generate a single file:

```bash
npm run bundle
```

Or run the full pipeline (extractor + bundler) in a single step:

```bash
npm run build
```

```html
<link rel="stylesheet" href="dist/bootstrap-dyn-bundle.min.css">
```

## 4. Demo Typography External Font Exception

For visual demo pages under `examples/demo/`, typography theme modules may include external web font imports (for example `@import` from Google Fonts) as a deliberate showcase choice.

This exception is allowed only under all of the following constraints:
1. Scope is limited to demo theme typography files (for example `examples/demo/theme/typography.css`).
2. The module must continue to define the canonical typography variables (`--bs-typo-*`) and related required dynamic variables (`--bs-dyn-*`) consumed by `bootstrap-dyn.css`.
3. The module must include robust local fallback font stacks so rendering remains functional when external font requests fail.
4. No non-typography component overrides may be introduced as part of this exception.
5. The production output contract in `dist/` remains unaffected; this exception does not apply to extractor output modules.

## 5. Bundler Integration

The bundler (`scripts/bundle.mjs`) uses this convention to locate and order files:

1. For each suffix in the canonical order, scan the input directory for a matching file (e.g., `*-color.css`).
2. For each fixed file, look for an exact name match.
3. Concatenate found files in the defined sequence.
4. Skip missing files (no error) to support partial theme directories.

### Excluding Modules

Use the `--exclude` flag to omit specific suffixes or fixed files from the bundle:

```bash
node scripts/bundle.mjs --exclude "contrast-dyn.css,-grid.css"
```

Excluded modules are skipped silently during concatenation and listed in the output.
