# BootstrapDyn — Demo

This directory contains four HTML pages that serve as a **visual compatibility test** for BootstrapDyn's modular theming system.

## Contents

| File | Description |
|------|-------------|
| [`dyn.html`](dyn.html) | Demo using BootstrapDyn CSS modules (dynamic variables) |
| [`org.html`](org.html) | Demo using the original `bootstrap.css` (reference) |
| [`theme.html`](theme.html) | Demo using CSS modules + custom theme |
| [`bundle.html`](bundle.html) | Demo using the single-file bundle (`bootstrap-dyn-bundle.min.css`) |
| [`theme/`](theme/) | Directory with custom theme CSS files |

## Purpose

These demos allow **visual compatibility verification** between two different validation modes:

1. **Parity mode (must be visually identical)**
   - **Original Bootstrap** (`org.html`) — loads `bootstrap.css` directly.
   - **BootstrapDyn with default values** (`dyn.html`) — loads the CSS modules generated by the pipeline. It should look **identical** to `org.html` since it uses the same original Bootstrap values, only through CSS variables.
   - **BootstrapDyn bundled** (`bundle.html`) — loads the single-file minified bundle (`dist/bootstrap-dyn-bundle.min.css`) instead of the 14 individual module files. It should look **identical** to `dyn.html` and `org.html`, proving that the bundler produces the same visual result with a single HTTP request.
2. **Theme mode (must remain compatible, not identical)**
   - **BootstrapDyn with custom theme** (`theme.html`) — replaces the default modules from `dyn.html` with matching custom theme modules (`theme/`). It should look intentionally different (colors, borders, shadows, spacing, typography), while preserving Bootstrap component behavior and compatibility.

## How to visually verify compatibility

### 1. Open all three pages in your browser

Open `dyn.html`, `org.html`, `bundle.html`, and `theme.html` in separate browser tabs. All should load without errors (check the browser console if needed).

### 2. Compare `dyn.html` vs `org.html` (visual parity)

These two pages should look **exactly the same**. Verify the following:

- **Top navbar**: The `bg-primary` navbar should display automatic contrast (white text on blue background) without needing `data-bs-theme="dark"`. This is handled by `contrast-dyn.css`.
- **Navbar colors**: All 8 navbar variants (primary, secondary, success, danger, warning, info, dark, light) must have correct contrast on text and links.
- **Buttons**: All solid and outline buttons, in all sizes and states (active, disabled), should render correctly.
  - Known exception in `org.html`: `btn-outline-light` over white backgrounds has low/no visible contrast (Bootstrap upstream issue: https://github.com/twbs/bootstrap/issues/39231).
  - In `dyn.html` and `bundle.html`, this is mitigated by `contrast-dyn.css`.
- **Grid**: Responsive columns, offsets, and gutters should work the same as in original Bootstrap.
- **Forms**: Inputs, selects, textareas, checks, radios, switches, ranges, and floating labels should look identical.
- **Interactive components**: Modals, offcanvas, toasts, dropdowns, tooltips, and popovers should open and close correctly.
- **Typography**: Headings, emphasis text, blockquotes, lists, and text colors should match.
- **Tables**: All variants (striped, hover, bordered, sm) should render correctly.
- **Cards, alerts, badges, progress, spinners, accordion, carousel**: All components should be visually identical.

> **If you find differences**, the module generation pipeline may have an issue. Re-run the pipeline with `node extractor/main.js` and execute tests with `npm test`.

### 3. Compare `theme.html` vs `dyn.html` (theme effect)

`theme.html` loads the same module categories as `dyn.html`, but each `theme/custom-*.css` file is a substitute for the matching `dist/default-*.css` file. You should notice the following changes:

- **Color palette**: Primary changes to teal (`#0f766e`), secondary to slate (`#475569`), and info to sky (`#0284c7`).
- **Body background and text**: Light background (`#f8fafc`) with dark text (`#0f172a`).
- **Border radius**: More pronounced than default (`.6rem` instead of `.375rem`).
- **Shadows**: Custom elevation scale with larger, softer shadows.
- **Contrast**: Contrast colors (`*-contrast`) adapt to the new palette.

> **If the theme is not applied**, verify that `theme/custom-*.css` files are loaded **instead of** the matching `dist/default-*.css` files and before `bootstrap-dyn.css` in the `<head>` of `theme.html`.

### 4. Quick check with the browser console

Open developer tools (F12) and run:

```javascript
// Check that CSS variables are defined
getComputedStyle(document.documentElement).getPropertyValue('--bs-primary').trim();
// dyn.html and org.html should return: #0d6efd
// theme.html should return: #0f766e
```

## Theme file structure

```
examples/demo/
├── dyn.html          ← BootstrapDyn (default values)
├── org.html          ← Original Bootstrap (reference)
├── theme.html        ← BootstrapDyn + custom theme
├── bundle.html       ← BootstrapDyn single-file bundle
└── theme/
    ├── custom-color.css      ← Color palette + contrast
    ├── custom-borders.css    ← Border tokens
    ├── custom-corners.css    ← Border radius
    ├── custom-forms.css      ← Form sizing
    ├── custom-grid.css       ← Grid module
    ├── custom-layers.css     ← Z-index layers
    ├── custom-layout.css     ← Breakpoints + containers
    ├── custom-motion.css     ← Transitions + animations
    ├── custom-shadows.css    ← Shadows + elevation
    ├── custom-sizing.css     ← Width/height sizing
    ├── custom-spacing.css    ← Spacing
    └── custom-typography.css ← Typography
```

Each theme file should be created by copying the matching `dist/default-*.css` file and changing values in the copy. Theme files are substitutes, so each one must provide all variables required for its concern.

## Notes

- The HTML markup of [`org.html`](org.html), [`dyn.html`](dyn.html), and [`bundle.html`](bundle.html) is the **parity baseline** and should remain aligned for visual comparison.
- [`theme.html`](theme.html) is a **theme validation page**: it may intentionally diverge visually from parity pages, but it must preserve Bootstrap component compatibility and interaction behavior.
- The shared demo styles in these pages are only a visual test harness: they organize sections, spacing, labels, side navigation, and component groups so the Bootstrap components can be compared clearly.
- Those demo styles must remain equivalent across the four pages and must not override Bootstrap component behavior or appearance in a way that would hide differences in the generated CSS. Do not add page-specific styles for buttons, cards, forms, navbars, tables, or other Bootstrap components.
- For parity pages (`org.html`, `dyn.html`, `bundle.html`), the **only routine edits** should be the CSS `<link rel="stylesheet" ...>` entries in `<head>`.
- For `theme.html`, markup/style updates are allowed when improving theme validation coverage, provided they do not hide regressions or bypass component behavior checks.
- All four pages load Bootstrap JS from `../../bootstrap/dist/js/bootstrap.bundle.js` for interactive components.
- `dyn.html`, `theme.html`, and `bundle.html` do **not** use `data-bs-theme` on navbars because `contrast-dyn.css` handles contrast automatically.
- `org.html` does use `data-bs-theme="dark"` on navbars because that is standard Bootstrap behavior.
- `bundle.html` loads `dist/bootstrap-dyn-bundle.min.css` (generated by `npm run bundle`) instead of the 14 individual module files. It must be regenerated after pipeline changes.

### Known upstream issue in original Bootstrap baseline

- In [`org.html`](org.html), `.btn-outline-light` may not display correctly on white backgrounds due to Bootstrap behavior (upstream issue: https://github.com/twbs/bootstrap/issues/39231).
- This should not be treated as a BootstrapDyn regression when validating parity.
- In BootstrapDyn demo pages that load `contrast-dyn.css` (`dyn.html`, `theme.html`, `bundle.html`), the contrast handling mitigates this case.

### Theme design principle

The custom theme files in [`theme/`](theme/) must produce **visually striking, immediately noticeable differences** compared to the default Bootstrap look:

- Subtle changes make it impossible to tell at a glance whether the theme is working correctly.
- Bold, distinctive choices — unusual color palette, exaggerated border-radius, dramatic shadows, distinctive typography — serve as a **stress test** for the theming system.
- If every CSS variable is properly wired through the pipeline, even extreme values should render correctly across all components.
- When comparing `theme.html` vs `org.html`, the difference should be obvious without zooming in or inspecting CSS.
